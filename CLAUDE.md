# Монитор сайтов с Telegram-ботом: правила работы

## Проект
Программа раз в 5 минут заходит на сайты как посетитель, проверяет, что они открываются и отвечают нормально, и при сбое шлёт сообщение в Telegram. Когда сайт ожил, шлёт «снова работает». Монитор только ЧИТАЕТ сайты, ничего в них не меняет.

Пользователь: вайбкодер, учится четвёртый месяц, цель: попасть в студию Webnum. Проект нужен, чтобы он понимал устройство и мог объяснить его на собеседовании.

## Как говорить
- По-русски, коротко и простыми словами. О себе в мужском роде.
- Перед каждым этапом называй размер (малый, средний, большой).
- Объясняй на бытовых примерах. Без длинных отчётов и без меню вопросов.
- Правда важнее вежливости: прямо называй ошибки, свои и его.

## Как работать
- Один этап за раз: сделал → проверил → объяснил, что сделал и зачем → коммит → СТОП. Следующий этап сам не брать.
- Часть кусков пользователь делает сам с подсказкой (список сайтов, текст сообщения). Говори, какие.
- «Готово» без доказательства не говорить: сказать, КАК проверено и что НЕ проверено.
- Перед этапом коротко спрашивай, что готово и что нельзя трогать.

## Секреты
- Токены и ключи никогда не печатать в чат и не читать в вывод. Пользователь кладёт их сам в `.env.local`.
- Проверять только «задано/не задано».
- `.env.local` в git не попадает.

## Окружение (Windows)
- Git Bash и PowerShell. Сложные команды писать в файл и запускать (`node файл.mjs`), а не через длинные кавычки.
- Node требует `--use-system-ca` (или `NODE_OPTIONS=--use-system-ca`).
- Файлы бывают с CRLF.

## Git
- Коммиты от аккаунта GitHub `bahshillaevbunyod-source`, почта `315207850+bahshillaevbunyod-source@users.noreply.github.com`.
- В конце сообщения коммита: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- После push проверять результат на деле, а не говорить «обновится через минуту».

## Этапы
1. Подготовка и схема.
2. Проверка одного сайта скриптом: код ответа, время, ключевой текст.
3. Список сайтов и правило «сбой» (2 плохих проверки подряд).
4. Telegram-бот: токен создаёт и вписывает пользователь.
5. Запуск по расписанию без компьютера (GitHub Actions или Vercel Cron, выбираем вместе).
6. Проверка: «роняем» тестовый адрес, ждём сообщение, «оживляем», ждём «снова работает».
7. Одна страница описания для собеседования.

Готово, когда пользователь сам получил в Telegram оба сообщения и может объяснить устройство своими словами.

## Сайты для проверки
Список лежит в `sites.json` (название, адрес, ключевой текст). Добавлять сайты туда, код не трогать. Ключевой текст подбираем на этапе 2.
- Проверяем только GET на главную страницу. Ничего не отправляем и не меняем.
- Autospace: только публичная главная, в CRM никогда не входить.
- kofe-nuqta.vercel.app отвечал 404: оставить или убрать, решает пользователь.
- NOVAÉ, Together и другие добавим позже.
