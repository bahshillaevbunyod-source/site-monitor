# Монитор сайтов с Telegram-ботом

## Что это
Программа, которая раз в час заходит на мои сайты как обычный посетитель и проверяет, что они открываются. Если сайт сломался, она пишет мне в Telegram. Когда сайт ожил, пишет «снова работает».

Аналогия: сторож обходит магазины и звонит хозяину, если дверь закрыта. Один раз не открыли: может, отошли, молчит. Не открыли дважды подряд: звонит. Потом не звонит каждый час, а ждёт, пока откроют, и звонит ещё раз.

Монитор только ЧИТАЕТ: один запрос GET на главную страницу. Ничего не отправляет и не меняет на сайтах.

## Как устроено

```
sites.json ──► check.mjs ──► monitor.mjs ──► telegram.mjs ──► Telegram
(список)      (проверка)     (правило        (отправка)        (мне)
                              «сбой»)
                                 ▲
                         state.json (память)
Всё запускает GitHub Actions по расписанию.
```

| Файл | Что делает |
|---|---|
| `sites.json` | Список сайтов: название, адрес, ключевой текст. Добавить сайт можно, не трогая код. |
| `check.mjs` | Проверяет один сайт: код ответа (нужен 200–299), время (дольше 3 с — «медленно», дольше 10 с — нет ответа), есть ли на странице ключевой текст. |
| `monitor.mjs` | Проверяет все сайты одновременно и решает, о чём сообщить (правило «сбой»). |
| `state.json` | Память между запусками: сколько плохих проверок подряд у каждого сайта и «лежит» ли он. |
| `telegram.mjs` | Отправка сообщения через Telegram Bot API. |
| `messages.mjs` | Тексты сообщений. Правятся отдельно от логики. |
| `.github/workflows/monitor.yml` | Расписание: каждый час в :07. Запускает монитор и сохраняет `state.json` в репозиторий, если он изменился. |

## Правило «сбой»
- Плохая проверка: код не 2xx, нет ответа за 10 с, ошибка соединения или нет ключевого текста.
- **2 плохих проверки подряд** → сообщение «не работает» (один раз).
- Первая хорошая проверка после этого → сообщение «снова работает».
- Одна случайная заминка между хорошими проверками сообщения не вызывает.
- Если Telegram не принял сообщение, состояние откатывается и отправка повторяется при следующем запуске. Тревога не теряется.
- Медленный ответ пока только помечается в логе, в Telegram не пишет.

## Зачем ключевой текст
Сайт может отвечать кодом 200, но показывать пустую страницу или страницу ошибки. Поэтому проверяю ещё и название бренда на странице.

## Секреты
`TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` лежат в `.env.local` на компьютере (в git не попадает) и в GitHub → Settings → Secrets (для облака). В коде и в репозитории их нет. Репозиторий публичный, поэтому это важно.

## Как проверено
- Проверка на живых сайтах и на заведомо сломанных: 404, неверный текст, несуществующий адрес.
- Тест логики правила на 11 шагах (в том числе случайная заминка и оживление после падения).
- Имитация сбоя отправки в Telegram: сообщение не ушло, состояние откатилось, при следующем запуске ушло, повторно не дублируется.
- В облаке: тестовый адрес (файл в репозитории) удалён → после 2 плохих проверок пришло 🔴 → файл возвращён → пришло 🟢. Оба сообщения я увидел в Telegram сам.

## Чего не проверено и ограничения
- **Запуск по расписанию.** Облачные запуски были ручными (кнопка «Run workflow»). Первый автоматический запуск по расписанию на момент написания не наблюдался. GitHub не гарантирует точное время: «раз в час» может опаздывать на минуты и больше.
- Если в репозитории 60 дней нет коммитов, GitHub может сам отключить расписание.
- Таймаут 10 секунд отдельным тестом не проверялся.
- Сайт `kofe-nuqta.vercel.app` отвечает 404 и числится «упавшим»: оставлен намеренно.
- Проверяется только главная страница, не вся работа сайта (формы, оплата, вход не проверяются).

## Почему такие решения (для собеседования)
- **GitHub Actions, а не Vercel Cron:** Vercel на бесплатном плане не запускает чаще, чем раз в 15 минут (по документации), а нужна была частота выше. GitHub Actions бесплатен для публичных репозиториев.
- **Раз в час и порог 2:** раз в день — узнаешь о падении почти через сутки; раз в 5 минут — GitHub всё равно опаздывает. Час с порогом 2 даёт обнаружение за 1–2 часа почти без ложных тревог.
- **Состояние в репозитории:** облачный запуск ничего не помнит, поэтому `state.json` сохраняется коммитом, но только когда изменился.
- **Список сайтов отдельным файлом:** чтобы добавлять сайты, не трогая код.

## Запуск вручную
```
node --use-system-ca --env-file=.env.local monitor.mjs
```
В облаке: GitHub → Actions → Monitor → Run workflow.
